# Architecture

This document outlines the proposed technical architecture for the Meta-Agent project.

## Meta-Agent Technology Stack

The project leverages a modern, service-oriented architecture, focusing on integration with existing advanced AI platforms and tools.

| Layer                 | Selected Technology/Service        | Key Features & Rationale                                       |
|-----------------------|------------------------------------|----------------------------------------------------------------|
| **Orchestration**     | LangGraph (Managed) + Flowise UI   | Graphical interface for building and managing stateful Agent Directed Acyclic Graphs (DAGs). Reduces boilerplate for complex agent interactions. |
| **Core Models**       | GPT-4o / Gemini-2.5 Pro / Grok 3 (via Azure AI Foundry) | Access to powerful foundation models with the ability to switch between them based on task requirements and availability. |
| **Coding & Execution**| GitHub Copilot Agent + AutoGen v2 Executor | Leverages Copilot for direct code generation and pull requests. AutoGen can be used for running scripts and more complex automated tasks. |
| **Knowledge Layer**   | Weaviate Cloud + Azure Cognitive Search | Provides "Retrieval-as-a-Service" capabilities, enabling robust and scalable RAG (Retrieval Augmented Generation). |
| **DevOps**            | Spacelift + AWS CodeGuru + Atlassian Intelligence | Aims for a fully AI-driven CI/CD pipeline, including infrastructure management, code analysis, and automated improvements. |
| **Interaction Interface**| Telegram / VS Code Plugin (potentially generated by Flowise) | Focuses on developer-centric interfaces, minimizing the need for custom frontend development. |

## Technology Selection Reference (from MVP Plan)

The initial MVP plan also considered the following for specific components:

-   **Information Collection**: Scrapy / Browserless + Playwright + LangChain Tools
-   **Knowledge Representation**: Vector Databases (Milvus / Weaviate) + OpenAI Embeddings
-   **Reasoning & Generation**: GPT-4o (with code-interpreter capabilities) + Function Calling
-   **Architecture Evaluation**: Rules-as-Code + Automated decision matrix scoring
-   **Initial Interface Ideas**: CLI / Telegram Bot / Web (Streamlit), with a view to upgrading to a VS Code plugin.

Many of these initial considerations are compatible with or encompassed by the broader technology stack outlined above. For instance, specific information collection tools can be integrated into LangGraph agents, and vector databases like Weaviate are explicitly part of the knowledge layer. The core model selection also aligns.
